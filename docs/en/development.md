# Development

How to work on Ren Browser locally.

## Requirements

- Go 1.27.3+
- Node.js 22+ and pnpm 12+
- Task (recommended)
- Reticulum config for live mesh tests (optional)

## Clone and run

```sh
git clone https://github.com/Quad4-Software/Ren-Browser.git
cd Ren-Browser
task dev
```

`task dev` runs Wails in development mode with Vite hot reload on port 9245 by default.

## Common tasks

| Task | Purpose |
|------|---------|
| `task dev` | Desktop dev mode |
| `task build` | Production build for current OS |
| `task run` | Run built binary |
| `task check` | Full quality gate (Go + frontend) |
| `task test` | All unit tests |
| `task test:e2e` | Playwright E2E against `renbrowser-server` |
| `task test:visual` | Visual regression vs `screenshots/` baselines |
| `task test:server:smoke` | Start server binary and verify HTTP |
| `task coverage:go` | Go coverage report under `coverage/` |
| `task coverage:frontend` | Vitest coverage under `coverage/frontend` |
| `task test:interop` | Live Reticulum tests (needs network) |
| `task build:server` | Headless server binary |
| `task run:server` | Run server locally |
| `task package` | Platform installer or bundle |

## Quality gate

Before you send changes:

```sh
task check
```

`check` runs:

- `gofmt` on Go sources
- `go test ./...`
- gosec security scan
- Brand consistency check
- Frontend typecheck, lint, format check, knip, audit, and vitest

Generate SPDX and CycloneDX SBOMs with Trivy:

```sh
task sbom
```

Optional harder Go tests:

```sh
task test:go:race
task test:go:hard
task fuzz:go
```

E2E and coverage:

```sh
task test:e2e
task test:visual
task coverage:go
task coverage:frontend
task test:server:smoke
```

## Portable CI

CI checks are **bash and Task only**. No dependency on GitHub Marketplace actions, composite actions, or other third-party workflow steps for the test logic.

| Command | Purpose |
|---------|---------|
| `task ci:pr` or `make ci-pr` | PR gate when Go, Node, pnpm, and Task are already on `PATH` |
| `bash build/scripts/ci/bootstrap.sh verify` | Fail fast if the toolchain is missing or too old |
| `bash build/scripts/ci/bootstrap.sh install` | Download pinned Go, Node, pnpm, and Task into `.cache/ci-toolchain` |
| `bash build/scripts/ci/run.sh <job>` | Run a job (`list` for names) |
| `bash build/scripts/ci/run-docker.sh pr` | PR gate in `build/docker/Dockerfile.ci` (uses **podman** when available, else docker) |
| `CI_CONTAINER=podman bash build/scripts/ci/run-docker.sh pr` | Force podman |
| `task ci:docker` | Wrapper for `run-docker.sh pr` |

Forgejo and Gitea: `.gitea/workflows/ci.yml` and `.forgejo/workflows/ci.yml` only run `bootstrap.sh install` and `run.sh`. The forge clones the repo into the workspace. No `uses: actions/*` steps.

Local quick run without `renbrowser.rsm` / `rnid`:

```sh
CI_SKIP_TREE_VERIFY=1 task ci:pr
```

Optional env:

- `CI_SKIP_TREE_VERIFY=1` skips signed tree inventory verify
- `CI_SKIP_SETUP=1` skips `setup.sh` when prep already ran
- `CI_TOOLCHAIN_ROOT` overrides the bootstrap install directory

Pinned versions live in `build/scripts/ci/versions.env`.

The large `.github/workflows/ci.yml` on github.com still uses Marketplace actions for matrix builds, caches, and releases. Use the bootstrap plus `run.sh` path above (or Gitea workflows) if you want CI without that stack.

## Frontend only

```sh
cd frontend
pnpm install
pnpm check
pnpm test
```

Bindings under `frontend/bindings/` are generated by Wails from Go services.

## Go layout

| Path | Role |
|------|------|
| `main_desktop.go` | Desktop entry (Wails window) |
| `main_server.go` | Server entry (HTTP only) |
| `internal/app/` | Browser service exposed to UI |
| `internal/rns/` | Reticulum stack wrapper |
| `internal/nomadnet/` | Page fetch over LXMF. NomadNet nodes are detected from announces, not from NomadNet libraries |
| `internal/micron/` | Micron rendering |
| `internal/store/` | SQLite persistence API |
| `internal/plugins/` | Extension host |
| `frontend/` | Svelte 5 UI |

See [Architecture](architecture.md) for a fuller map.

## Plugin development

```sh
task test:plugins
```

Install your dev plugin into `~/.renbrowser/plugins/` and reload the app.

## Interop tests

```sh
task test:interop
```

Requires a live Reticulum network and the `interop` build tag. Skip for UI-only work. Optional GitHub workflow: `.github/workflows/interop.yml`.

## Asset probe

Set `REN_BROWSER_ASSET_PROBE=1` when debugging which asset loader (embedded vs disk) is active.

## SPDX headers

Match existing style in neighboring files.
